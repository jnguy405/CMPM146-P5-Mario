Individual_DE: What We Can Change (based on ga.py Grid implementation)
------------------------------------------------------------------------
Design Element encoding (Individual = Individual_DE)

MUTATION (Individual_DE.mutate)
--------------------------------------
- Currently: 10% chance per genome to mutate one random design element; by type, perturb
  x/y/w/h or flip a boolean. "2_enemy" is not mutated (pass).
- Changes to consider:
  - Add a config constant (e.g. DE_MUTATION_RATE = 0.1) instead of hardcoding 0.1.
  - Per-element mutation: with some probability, mutate each DE in the list (like
    per-gene in Grid), or keep current “mutate one random DE” but make rate configurable.
  - Implement mutation for "2_enemy" (e.g. offset x with offset_by_upto) so enemies
    can move; otherwise new_de is never set and the same DE is re-pushed.
  - Add constraints (e.g. keep pipe height/position valid, avoid overlapping DEs) as
    suggested by STUDENT comments.

CROSSOVER (Individual_DE.generate_children)
----------------------------------------------
- Currently: Single-point style on the list of DEs—pick pa in self, pb in other;
  child1 = self[:pa] + other[pb:], child2 = other[:pb] + self[pa:], then mutate both.
  Returns two children (Grid returns one).
- Changes to consider:
  - Make crossover mode configurable (e.g. same CROSSOVER_MODE or a DE-specific one):
    - Uniform: merge the two lists (e.g. by interleaving or by position) and at each
      “slot” choose with 0.5 probability from parent A or B (need a rule when list
      lengths differ).
    - Multi-point: treat concatenated or merged list as a sequence, pick multiple
      cut points, alternate segments from self and other (then re-heapify).
  - Document in write-up: “Crossover splits each parent’s list at a random index and
    recombines the segments to form two children.”

CONFIG
--------
- Add DE-specific constants at top if desired (e.g. DE_MUTATION_RATE, DE_CROSSOVER_MODE)
  so both encodings can be tuned without editing class code.

OTHER
